# 표준시방서 취합 프로그램

Windows와 설치된 한컴오피스 한글을 사용하는 로컬 프로그램입니다. 이 PC의 한글 2022를 기준으로 개발했습니다.

현재 배포본은 테스트용입니다. 기존 119공종 생성 결과는 목차 쪽 번호와 PDF 책갈피를 확인했지만, 회사 납품본의 표지·목차 표·검은 장 제목 띠와의 양식 차이, 일부 집필위원/판권 잔여 페이지는 아직 정리되지 않았습니다. 다른 PC의 한글 버전별 실행은 별도 테스트가 필요합니다.

## 사용 순서

1. `표준시방서 취합 프로그램.exe`를 실행합니다.
2. 프로젝트명, 회사명, 적용 기준일과 회사 양식 파일을 확인합니다.
3. 실행 시 공식 개정 이력을 자동으로 조회하고 내장 원본을 업데이트합니다. 다시 확인하려면 **최신 시방서 확인·업데이트**를 누릅니다. 개정일과 시행일이 표시됩니다.
4. 내장된 회사 기본 **119개 공종**에서 시작합니다. 회사 양식이 바뀌었다면 **회사 통합본 공종 읽기**를 누릅니다. 사용자가 낱장 파일을 별도로 내려받거나 폴더를 지정할 필요는 없습니다.
5. 도면·내역서를 보고 공종을 포함/제외합니다. 체크 칸 클릭 또는 행 더블클릭/스페이스로 전환합니다. 강구조를 포함한 모든 공종은 같은 체크박스로 선택합니다.
6. 공종 확인 체크 후 **선택 기준으로 한글 + PDF 생성**을 누릅니다.
7. `개정·적용검토표.csv`와 PDF를 확인합니다. **선택 저장**으로 프로젝트 설정을 저장해 다음 수정 때 불러옵니다.

생성 중 한글 창이 열립니다. 한글의 파일 접근 허용 창이 표시되면 사용자가 내용을 확인해 직접 허용해야 합니다. 프로그램은 보안 설정을 변경하지 않습니다. 생성용 한글 창에서 동시에 편집하지 마세요.

## 생성되는 파일

- `01. 표준시방서.hwp`: 편집 가능한 통합 한글 문서. 표지, 번호가 붙은 목차, 선택 기준 본문, 연속 쪽 번호.
- `01. 표준시방서.pdf`: 한글에서 변환한 통합 PDF. 각 공종의 PDF 책갈피 포함.
- `개정·적용검토표.csv`: 개정일, 시행일, 시작/끝 쪽, 제외된 참조기준, 공식 원문 URL, 원본 SHA-256.
- `검토기록.json`: 조회 시각, 프로젝트 설정, 원본/양식 해시, 처리 방식 및 결과.
- `project.json`: 이번에 선택한 공종과 순서. 다시 불러올 수 있습니다.
- `편집원본/`: 공종별 회사 양식을 적용한 HWP. 수정 참고용입니다.

기본 결과 폴더는 `%LOCALAPPDATA%/HAEMA/StandardSpec/결과물`입니다. 화면에서 원하는 납품 결과 폴더로 바꿀 수 있습니다. 실행할 때마다 시간 이름의 새 폴더에 저장하며 회사 통합본과 기존 결과 파일을 덮어쓰지 않습니다.

## 프로그램 EXE 업데이트

프로그램은 `haemasue-alt/UnifiedConstructionSpecification`의 GitHub Releases에서 새 정식 버전을 확인합니다. 현재 프로그램 버전은 **1.1.2**입니다. 새 버전이 있으면 **업데이트하시겠습니까?**를 표시하고, 수락한 경우에만 EXE를 다운로드해 GitHub의 SHA-256·파일 크기와 대조한 뒤 교체·재실행합니다. 거절하거나 조회가 실패하면 현재 버전으로 계속 사용합니다. 각 PC의 기존 시방서·회사 양식·프로젝트 자료는 유지하며 이전 EXE는 앱 데이터의 `updates`에 보관합니다.

비공개 저장소는 해당 저장소를 읽을 수 있는 GitHub 계정의 접근 토큰이 필요합니다. 각 PC에서 최초 한 번 **도움말 → GitHub 접근 토큰 설정 (비공개 저장소)**에 입력합니다. Fine-grained token은 이 저장소만 선택하고 **Contents: Read-only** 권한을 부여합니다. 토큰은 Windows 자격 증명 관리자에 사용자별로 저장하며 EXE·JSON 설정 파일에 포함하지 않습니다. 토큰 만료나 접근 권한 변경 시 해당 PC에서 갱신합니다. 저장소 주소는 **GitHub 업데이트 저장소 설정**에서 변경할 수 있습니다.

비공개 저장소 접근 권한이 없으면 GitHub는 HTTP 404를 반환합니다. 프로그램은 저장소 접근 실패와 정식 Release 미등록을 구분해 안내합니다. 접근 설정 후에도 아직 정식 Release를 게시하지 않았다면 관리자가 아래 순서로 최초 배포본을 게시해야 합니다. 이때 국가건설기준센터 시방서 원본 확인은 별도로 계속 진행됩니다.

새 디자인·버튼 수정본을 배포하려면 다음 순서로 진행합니다.

1. `spec_update.py`의 `APP_VERSION`을 올립니다. 예: `1.1.2` → `1.1.3`.
2. `python package_single.py`로 새 EXE를 빌드하고 검증합니다.
3. GitHub 저장소의 **Releases → Draft a new release**에서 같은 버전의 태그 `v1.1.3`을 사용합니다. 처음 게시할 때는 현재 배포본 버전에 맞춰 `v1.1.2`를 사용합니다.
4. 검증한 `dist/표준시방서 취합 프로그램.exe`를 GitHub 첨부파일 이름 **HaemaStandardSpec.exe**로 올리고 정식 Release로 게시합니다. GitHub는 한글 파일명을 `default.exe`로 바꿀 수 있어 서버에서는 영문 이름을 사용합니다. 사용자 PC의 실행 파일 이름은 `표준시방서 취합 프로그램.exe`를 유지합니다. 초안·시험판은 자동 업데이트 대상에서 제외합니다.
5. 다른 PC가 다음 실행할 때 새 버전 안내를 받습니다. 소스 코드만 커밋하거나 EXE를 일반 파일로 올리는 것으로는 배포되지 않습니다.

기존 1.1.0~1.1.1 EXE는 GitHub에서 변경되는 한글 첨부파일 이름을 처리하지 못하므로 이번 배포본을 한 번 직접 복사해야 합니다. 이후 배포본은 영문 서버 파일명을 사용하며 기존 실행 파일 경로에서 교체·재실행합니다. 프로그램 EXE 업데이트와 국가건설기준센터 시방서 원본 확인은 별도로 동작합니다. 업데이트 실패 기록은 앱 데이터의 `updates/update_error.log`에 저장됩니다.

## 내장 자료와 자동 업데이트

내 PC와 다른 PC 모두 같은 `표준시방서 취합 프로그램.exe` 하나를 사용합니다. EXE만 복사하면 됩니다. 처음 실행하면 내장된 회사 기본 119개 공종 원본·양식 적용 캐시·공통/건축 한글 양식을 `%LOCALAPPDATA%/HAEMA/StandardSpec`에 자동 준비합니다. 일반적으로 `C:/Users/사용자명/AppData/Local/HAEMA/StandardSpec`입니다. EXE 옆에 `_internal`, `data` 폴더를 만들지 않습니다. 실행에 필요한 라이브러리는 Windows 임시 폴더에서 준비되고 정상 종료 후 정리됩니다.

기존의 EXE 옆 `data` 폴더가 있으면 없는 자료를 앱 데이터로 가져옵니다. 이미 업데이트된 자료와 사용자가 수정한 양식은 덮어쓰지 않습니다. EXE를 옮기거나 교체해도 같은 Windows 사용자 계정의 자료는 유지됩니다. 다른 사용자 계정은 별도의 자료 폴더를 사용합니다. 기본 사용에는 회사 공유폴더 연결이 필요하지 않으며 한글/PDF 생성에는 설치된 한컴오피스 한글이 필요합니다.

**도움말 → 프로그램 자료 폴더 열기 / 사용 안내 / 3공종 검증샘플 불러오기**에서 보관 자료와 안내를 확인할 수 있습니다. 오류 기록은 앱 데이터의 `data/last_error.log`, 시작 오류는 `startup_error.log`입니다. 관리 권한 없이 실행할 수 있습니다.

실행할 때 국가건설기준센터의 공식 목록을 조회하고 회사 기본 공종별 파일 ID를 대조합니다. 보관한 파일의 SHA-256을 검증해 재사용하며, 새로운 개정본이나 손상된 원본은 공식 사이트에서 받습니다. 원본은 개정별 폴더에 보관해 이전 파일을 지우지 않습니다. 모든 공종을 확인한 뒤 `data/current.json`을 갱신합니다. 해당 파일에는 공식 URL, 파일 ID, 개정일·시행일, 조회 시각, SHA-256이 남습니다. 이 검증은 공식 개정 이력과 보관 파일을 대조하는 방식이며, 변경 없는 원본을 서버에서 매번 다시 다운로드하는 방식은 아닙니다.

현재 시행 중인 최신본을 자동 확보합니다. 미래 시행본을 현재 기준으로 적용하지 않으며, 과거 기준일의 프로젝트는 그 날짜에 적용되는 이력을 사용합니다. 기본 목록 밖의 공종은 목록에서 직접 선택하면 생성 시 필요한 원본을 받습니다. 신규 공종을 프로젝트에 임의로 추가하지 않습니다.

인터넷 오류나 다운로드 실패 시 이전 내장 목록을 유지하고 **최신 확인 실패 / 기존 자료 보존**을 표시합니다. 생성 직전에도 공식 목록을 다시 조회하므로 인터넷 연결이 필요합니다. 새 원본은 생성 시 회사 양식을 다시 적용하며, 이전 개정본의 변환 캐시를 재사용하지 않습니다. 프로그램을 닫아둔 동안에는 업데이트하지 않습니다.

## 회사 공용 자료실 (선택 사용)

기본 자료실은 `\\192.168.4.20\haema_ai\표준시방서`입니다. **공용 목록 다시 읽기**를 누르면 공용 현행 목록의 공종과 양식 경로를 적용합니다. 기본 시작 화면은 내장 자료를 사용합니다. 프로젝트 선택을 불러오면 그 프로젝트의 선택이 적용됩니다.

상단 **공용 자료** 메뉴에서 목록을 다시 불러오거나 공식 원본을 업데이트하고 자료실을 열 수 있습니다. 업데이트는 공용 관리 목록에 등록된 공종 전체를 확인합니다. 프로젝트에서 강구조를 제외해도 공용 자료실에서는 삭제하지 않습니다. 초기 119개는 기존 회사 통합본의 수록 공종이며 실제 사용 빈도를 분석한 결과는 아닙니다.

- `00_관리/현행기준목록.csv`: 개정일·시행일·조회 시각·공식 출처·파일 경로·회사 양식본 상태.
- `01_공식원본`: 공식 원문. 편집하지 않고 사용합니다.
- `02_회사양식본`: 회사 양식을 적용한 공종별 편집본. 최종 검토 후 납품에 사용합니다.
- `03_회사기본양식`: 제공된 공통/건축 한글 양식.

변경된 자료가 있으면 새 날짜 폴더에 저장하고 이전 날짜 폴더는 보존합니다. 모든 복사와 SHA-256 검증 후 `현행목록.json`을 교체합니다. 동일 자료로 다시 업데이트하면 파일을 중복 저장하지 않습니다. 동시 업데이트는 잠금 파일로 막습니다. 비정상 종료 후 `00_관리/업데이트중.lock`이 남으면 진행 중인 작업이 없는지 확인한 뒤 관리자가 해당 파일만 제거하세요.

공식 개정본에 대응하는 회사 양식 변환 캐시가 없으면 **회사 양식 변환 필요**로 표시합니다. 해당 공종을 프로그램에서 생성한 후 다시 공용 업데이트하면 적용본이 등록됩니다. 내장 원본은 실행 시 자동 확인하며, 공용 자료실에 올리는 작업은 메뉴에서 수동 실행합니다.

PDF 생성 직전에 공식 개정 이력을 다시 조회하며, 공용 원본은 공식 파일 ID와 SHA-256이 일치하는 경우에 재사용합니다. 공용 원본이 오래되거나 손상되면 공식 사이트에서 다시 내려받습니다.

## 최신 여부와 프로젝트 적용

공식 출처는 [국가건설기준센터](https://www.kcsc.re.kr/)입니다. 공개 목록의 개정 이력에서 프로젝트 기준일에 개정·시행되고 사용 가능한 이력을 골라 그 이력의 파일을 내려받습니다. 미래 시행본과 적용 종료 이력을 구분합니다. 생성 직전에 목록을 다시 조회하며, 인터넷 조회가 실패하면 최신으로 확인했다고 처리하지 않습니다.

보유본의 `(24.05)` 같은 파일명 날짜는 참고값입니다. 월이 같다는 이유로 내용까지 최신이라고 판정하지 않습니다. 결과에는 공식 파일 ID, 원본 해시, 조회 시각을 남깁니다. 기준일 이전의 용역에서 종전 기준을 쓰는 등의 프로젝트 적용 판단은 담당자가 합니다.

공종 선택은 담당자 체크 방식입니다. 도면이나 내역서를 자동으로 해석하는 기능은 없습니다. 본문에서 인용한 KCS 중 선택하지 않은 코드를 검토표에 표시하므로 참조 관계를 추가로 확인할 수 있습니다. 인용되었다는 이유로 공종을 임의로 추가하지 않습니다.

## 회사 양식 적용 범위

제공한 공통부분/건축공사부분 HWP의 실제 스타일을 읽어 본문, 제목 단계, 코드 제목, 용어 문단, 글꼴, 여백에 적용합니다. 공식 파일의 표지·자체 목차와 명확한 집필위원 명단을 분리합니다. 기술 부록은 유지합니다. 표·그림·수식의 내부 내용과 원본 객체를 보존하며 표 내부의 개별 양식은 원본 형식을 유지합니다. 가로 용지 구역은 보존합니다.

한글이 계산한 실제 페이지를 읽어 목차를 갱신하고 PDF 변환 후 시작 쪽, 전체 쪽 수, 연속 쪽 번호를 대조합니다. 원본 구조가 달라 본문을 안전하게 구분하지 못하면 작업을 멈추고 해당 코드를 안내합니다. 그 항목을 선택해 **원본 전체 유지 전환**으로 표지와 부록까지 포함한 검토용 취합을 만들 수 있습니다.

표나 그림이 많은 공종은 최종 PDF에서 넘침·줄바꿈을 확인하세요. 한글에서 직접 본문을 수정한 뒤에는 그 수정본을 자동으로 다시 읽어 목차를 갱신하지 않습니다. 공종과 공식 개정본 선택을 바꾼 후 프로그램으로 다시 생성하는 흐름입니다. 직접 수정 내용을 재사용하는 기능은 포함하지 않습니다.

공식 원본에 변경 추적이 켜진 경우 검토표에 표시합니다. 한글의 HWPML 변환은 변경 이력을 최종 상태로 합치므로 해당 항목은 공식 원본과 대조하세요. 공식 원본 자체는 수정하지 않습니다.

공식 API나 한글 버전이 바뀌면 연결/변환 수리가 필요할 수 있습니다. 원본 캐시는 `data/originals`, 동일 원본·양식의 변환 캐시는 `data/normalized`, 회사 양식의 스타일 캐시는 `data/company`에 저장됩니다. 원본 또는 양식의 내용이 바뀌면 캐시를 다시 만듭니다.

## 소스 실행과 검증

```powershell
python -m pip install pywin32 pypdf pyinstaller
python app.py
python -X utf8 verify.py
python -X utf8 verify.py --integration
python package_single.py
```

통합 검증은 실제 공식 원본 3개(공사일반, 강구조공사 일반사항, 유리공사)를 다운로드해 회사 양식과 함께 처리합니다. 회사 원본 불변, 기술 본문 보존, 날짜/시행 이력, 목차/페이지와 PDF 책갈피를 확인합니다.
